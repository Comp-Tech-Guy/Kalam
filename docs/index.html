How It Works

Three simple steps to a fully customized desktop.

1

Create Profile

Give your profile a name and select which tools to include. Each profile is a complete desktop blueprint.

2

Configure Tools

Set up each tool exactly how you want it — Rainmeter layouts, YASB styles, GlazeWM workspaces, and more.

3

Apply

Click Run on any profile to switch your entire desktop environment. Everything changes at once.

Supported Tools

Kalam manages every aspect of your desktop setup through a single interface.

GlazeWM

Window manager config. Swap between tiling layouts and workspace setups seamlessly.

YASB

Config YAML + styles CSS injection. Full control over your taskbar appearance and behavior.

Rainmeter

Layout selection and activation. Pick from your installed Rainmeter layouts and apply them instantly.

Zebar

Status bar settings. Customize system monitors, clock, and quick-access widgets.

Wallpaper

Desktop background across virtual desktops. Set unique wallpapers that persist per profile.

Windhawk

Mod enable/disable + per-mod settings. Fine-tune Windows shell mods without manual registry edits.

Komorebi

Tiling window manager config. Workspaces, layouts, and window management rules for a programmable desktop.

Bloom

Dynamic Island notch + dock settings. Give Windows a modern glanceable status bar and dock.

Privacy Policy

Introduction

Kalam is an open-source, profile-based desktop environment manager for Windows. This Privacy Policy explains what data Kalam accesses, how it is used, and what it does not do with your information.

We believe in transparency. Kalam is designed to work entirely on your device. Your data stays yours.

Information We Collect

Kalam does not collect, transmit, or sell any personal data. There is no account system, no analytics, no telemetry, and no user tracking of any kind.

Kalam does access and store the following data locally on your device only:

Data Stored by Kalam

DataLocationPurpose
Application settings%APPDATA%/Kalam/userSettings.jsonStores your theme preference, onboarding state, and paths to managed tools
Desktop profiles%APPDATA%/Kalam/userProfiles.jsonStores the profiles you create — profile names, enabled tools, tool-specific configurations, and wallpaper paths
Tool manifest cacherainmeterManifest.json, yasbManifest.json, glazewmManifest.json, zebarManifest.json, windhawkManifest.jsonCached copies of tool configurations written during scan to track the current state of each tool

Data Read from Your Device

To apply desktop profiles, Kalam reads configuration files from the following tools installed on your system:

ToolWhat Kalam Reads
RainmeterLayout files in %APPDATA%/Rainmeter/Layouts/
YASBconfig.yaml and styles.css from ~/.config/yasb/ or ~/.yasb/
GlazeWMconfig.yaml from ~/.glzr/glazewm/ or ~/.glzewm/
Zebarsettings.json from %APPDATA%/zebar or ~/.zebar/
WindhawkMod enabled/disabled state and per-mod settings from the Windows registry or a portable directory
WallpaperImage files from paths you specify in your profiles
Komorebikomorebi.json and applications.json from KOMOREBI_CONFIG_HOME or your home directory
Bloomsettings.json from %APPDATA%/com.sehaz.bloom/ (notch + dock configuration)

None of this data leaves your device. Kalam reads and writes these files solely to apply and manage your desktop profiles.

How Your Data Is Used

All data accessed or stored by Kalam is used exclusively for the following purposes:

  • Profile management — Creating, editing, storing, and applying desktop configuration profiles
  • Tool configuration — Reading and writing configuration files for managed tools on your local system
  • Application preferences — Remembering your theme choice, tool paths, and onboarding state

Kalam does not use your data for advertising, analytics, profiling, or any purpose other than those described above.

Network Activity

Kalam makes one type of network request: an automatic update check.

Auto-Update Check

  • What it does: On startup and when manually triggered from Settings, Kalam contacts the GitHub Releases API to check if a newer version is available
  • What is sent: The current version number of Kalam installed on your device. No personal data, no device identifiers, no usage data
  • What is received: A JSON response indicating whether a newer release exists, along with release notes and download URLs
  • When it happens: Automatically on app launch, or manually when you click "Check for Updates" in Settings

If you choose to download an update, the download is served directly from GitHub Releases. Kalam does not proxy, log, or track this download.

No Other Network Activity

Kalam does not:

  • Connect to any servers other than GitHub's release API
  • Send telemetry or usage statistics
  • Use any analytics services
  • Communicate with any third-party tracking services
  • Use cookies, web beacons, or similar technologies

Third-Party Services

Managed Tools

Kalam interacts with several third-party tools to apply your desktop profiles. Each tool is independent and has its own privacy policy:

  • Rainmeter
  • YASB
  • GlazeWM
  • Zebar
  • Windhawk

Kalam does not share data with these tools beyond what is necessary to apply configurations.

Data Sharing

We do not sell, rent, trade, or share your data with anyone.

Kalam does not transmit any user data to us, to advertisers, to analytics providers, or to any third party. The only network communication from Kalam is the version check with GitHub, which does not involve any personal data.

Data Storage and Security

  • All Kalam data is stored locally on your Windows device in %APPDATA%/Kalam/
  • Data files are standard JSON files protected by your operating system's file permissions
  • Kalam does not encrypt these files separately — they are protected by the same access controls as the rest of your user profile directory
  • No data is stored on external servers or in the cloud by Kalam

Changes to This Privacy Policy

We may update this Privacy Policy from time to time. Any changes will be reflected in the "Last Updated" date at the top of this document. Significant changes will be communicated through the in-app update banner and the GitHub repository.
